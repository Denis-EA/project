!!! info "Цель урока"
    Научиться применять классы эквивалентности и граничные значения — два главных инструмента тест-дизайна. Составить свой первый чек-лист.

---

## Что такое тест-дизайн?

Тест-дизайн — это **искусство выбирать минимум проверок, которые найдут максимум багов**. Невозможно протестировать всё (в любом приложении тысячи сценариев), поэтому тестировщик должен уметь выделять главное.

!!! tip "Аналогия"
    Представьте, что вам нужно проверить, работает ли лифт в 100-этажном здании. Вы же не будете ездить на каждый этаж с каждым возможным весом? Вы проверите:
    
    - Пустую кабину (0 кг)
    - Среднюю загрузку (400 кг — 5 человек)
    - Максимальную загрузку (1000 кг — предел)
    
    Это и есть тест-дизайн: выбрать ключевые точки вместо тысячи бессмысленных проверок.

---

## Классы эквивалентности

**Классы эквивалентности** — это группы данных, которые приложение обрабатывает одинаково. Достаточно проверить одно значение из группы, чтобы убедиться, что вся группа работает.

### Пример: Поле "Возраст" (допустимые значения: 18–65 лет)

```mermaid
    A[Все возможные значения] --> B[Невалидные: < 18]
    A --> C[Валидные: 18–65]
    A --> D[Невалидные: > 65]
    
    B --> B1["Проверить: 0, -5, 17"]
    C --> C1["Проверить: 18, 30, 65"]
    D --> D1["Проверить: 66, 100, 200"]
```
```mermaid
Класс	        Диапазон	Что проверять	Ожидаемый результат
Невалидный 1	Меньше 18	0, -5, 17	    Ошибка "Вам должно быть 18+"
Валидный	    18–65	    18, 30, 65	    Поле принимает значение
Невалидный 2	Больше 65	66, 100, 200	Ошибка "Максимальный возраст — 65"


!!! success "Правило одного представителя"
Если вы проверили значение 30 из валидного класса и оно работает, скорее всего, значения 25, 40, 55 тоже сработают. Не нужно проверять все подряд — это экономит часы тестирования.

Граничные значения
Граничные значения — это точки на стыке классов эквивалентности. Баги чаще всего прячутся именно на границах.

Пример для того же поля "Возраст" (18–65)
graph LR
    A[17] --> B["Граница: 18"]
    B --> C[Валидные значения]
    D[65] --> E["Граница: 66"]
    E --> F[Невалидные]
    
    style B fill:#ff6e40,color:#fff
    style E fill:#ff6e40,color:#fff

```mermaid
Точка	            Значение	Тип	        Почему важно
Нижняя граница — 1	    17	    Невалидный	Часто путают со знаком "≥"
Нижняя граница	        18	    Валидный	Минимально допустимое
Верхняя граница	        65	    Валидный	Максимально допустимое
Верхняя граница + 1	    66	    Невалидный	Часто путают со знаком "≤"
```

!!! warning "Золотое правило тестировщика"
Всегда проверяйте границы минус 1, границу, границу плюс 1. Именно здесь разработчики чаще всего ошибаются в условиях if age >= 18 vs if age > 18.

Составляем первый чек-лист
Чек-лист — это краткий список того, что нужно проверить. В отличие от тест-кейса, в чек-листе нет подробных шагов — только суть проверки.

Пример чек-листа для формы регистрации
```mermaid
№	Что проверяем	                            Результат
1	Регистрация с валидными данными	            ☐ Pass / ☐ Fail
2	Поле "Имя" пустое	                        ☐ Pass / ☐ Fail
3	Поле "Имя" содержит цифры	                ☐ Pass / ☐ Fail
4	Поле "Email" без символа @	                ☐ Pass / ☐ Fail
5	Поле "Email" с пробелом в середине	        ☐ Pass / ☐ Fail
6	Пароль меньше 8 символов	                ☐ Pass / ☐ Fail
7	Пароль без заглавной буквы	                ☐ Pass / ☐ Fail
8	Пароль из одних пробелов	                ☐ Pass / ☐ Fail
9	Возраст меньше 18	                        ☐ Pass / ☐ Fail
10	Возраст ровно 18	                        ☐ Pass / ☐ Fail
11	Возраст больше 120	                        ☐ Pass / ☐ Fail
12	Согласие на обработку данных не отмечено	☐ Pass / ☐ Fail
```

!!! tip "Как составлять хороший чек-лист"

Один пункт = одна проверка. Не смешивайте "Проверить логин и пароль" в одном пункте.

Пишите кратко. "Кнопка Войти неактивна при пустом логине", а не "Открываем страницу, вводим логин..."

Используйте классы эквивалентности и границы. Это ваш каркас для чек-листа.

Ключевые термины урока
!!! abstract "Глоссарий"

Тест-дизайн — методика отбора тестов для максимального покрытия при минимальных затратах.

Класс эквивалентности — группа значений, которые приложение обрабатывает одинаково.

Граничные значения — значения на стыке классов, где вероятность бага максимальна.

Чек-лист — краткий список проверок без подробных шагов.
